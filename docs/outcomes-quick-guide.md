# Project outcomes: quick guide

Three steps. Everything is on the project's **Outcomes** tab.

```
1. REGISTER (once)          2. REPORT (monthly)            3. APPROVE (PI)
PI / lead                   Owner RA                       PI
Contract deliverables  -->  New stage + evidence      -->  Approve the update
with an owner RA            in the monthly update          (or set the stage directly)
                                                           -> the report updates itself
```

## 1. Register: PI, lab manager or project lead, once per project

Outcomes tab → **Register or change outcomes**, then pick one way in:

- **Template:** CEI, VinIF or Industry, then edit the titles.
- **Paste:** one line each, `kind; title; due date`. For example: `Journal; Twin paper; 2027-06-30`, `BMS; BMS v1; 2027-03-31`, `Testbed; HiL bench`.
- **One by one:** with **Add one**.

Give every deliverable an **owner RA**: only the owner reports on it.

**From the RA's page instead:** RAs → open the RA → **Assigned deliverables and tasks** → **Assign a deliverable**. Choose one of the RA's projects, the kind (or "Task" for a work step), title, work package and due date. It's the same record as on the project's Set up, owned by that RA. The section also lists everything the RA owns across their projects, and the RA sees the same list on their own page.

| Kind | Stages (%) |
|---|---|
| Journal or conference paper | Planned 0 · Drafting 25 · Submitted 50 · Revision 70 · Accepted 90 · Published 100 |
| Product or prototype (BMS, device, controller, software) | Planned 0 · Design 25 · Build 50 · Testing 75 · Validated 100 |
| Testbed | Planned 0 · Design 30 · Build and commissioning 60 · Operational 100 |
| Model or method (CFD or reduced-order model, surrogate, algorithm, optimization method) | Planned 0 · Developing 40 · Validated 80 · Delivered 100 |
| Patent | Planned 0 · Disclosure 40 · Filed 80 · Granted 100 |
| Report | Planned 0 · Drafting 50 · Delivered 100 |
| Activity (task) | A work step that is not a deliverable; it does not count in progress %. Tasks have their own **Tasks** tab |

## 2. Report: the owner RA, every month

My work → the month's update → for each outcome, pick the **Stage now** and add the **evidence** that stage asks for:

| Stage reached | Evidence |
|---|---|
| Submitted | the submission confirmation |
| Accepted | the acceptance email |
| Published | the DOI or link |
| Validated (product) | the test report, photo or demo link |
| Operational (testbed) | the commissioning report |
| Validated (model or method) | the validation report or comparison with measurements |
| Delivered (model or method) | the code, model files or method report |

Then press **Send for checking**. Don't add the same paper or prototype again under Outputs.

## 3. Approve: the PI

- **Usual way:** the lab manager checks the update, and the PI approves it in **Updates waiting**.
- **Between updates:** on the Outcomes tab, press **Set stage**, choose the stage, add the evidence and save. Use it, for example, when an acceptance email arrives mid-month.

Either way, a paper that reaches Submitted, or a prototype or testbed that reaches its last stage, is added to the RA's outputs automatically. The progress report and slides update by themselves.
